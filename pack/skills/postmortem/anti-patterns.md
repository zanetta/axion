# Anti-Patterns

| Anti-pattern | Why | Do instead |
|--------------|-----|------------|
| Blame / naming villains | Hides systemic causes | Blameless framing; conditions + actions |
| No action items | Learning evaporates | Owner + deadline + done-when |
| “Human error” as root cause | Stops inquiry | Ask what made the error easy |
| IR dump as postmortem | War-room chat ≠ analysis | Stabilize first; rewrite as structured doc |
| Speculative timeline | False lessons | Separate facts vs hypotheses |
| Secrets / PII / full logs in doc | Leak + retention risk | Redact; link to controlled stores |
| Endless draft, never published | No shared memory | Time-box; ship draft then refine |
| Only tech fixes, ignore process | Recurrence via same path | Include detect/respond/learn items |
| Close tickets without verification | Fake completion | Enforce “done when” |

## Review gate

Before publish: blameless tone, timeline factual, ≥1 prevention or detection action for each major factor, no secrets/PII, tickets linked.
